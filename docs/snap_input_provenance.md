## Semantic regeneration audit

The deterministic `scripts/prepare_snap_two_community.py` program was run in a temporary directory using each existing remapped community file as a `0/1` mapping and each existing remapped edge file as its edge input. For all three networks:

- node count, edge count, and both community sizes matched;
- the node-to-community mapping matched exactly;
- the canonical undirected edge sets matched exactly; and
- there were zero edges unique to either the existing or regenerated set.

The generated byte representation can differ from a legacy file because the new program applies stable sorting, canonical endpoint orientation, LF line endings, and duplicate removal. Semantic equivalence, rather than byte identity, is the relevant validation here.

## Unresolved original-source provenance

A legacy `remap_community_edge.py` was found outside this repository. It renumbers nodes in input-row order and remaps a previously selected community file; it does not record how the two source communities were chosen. The original community IDs and the original node-community selection files used for the three formal inputs were not found. They are therefore not guessed.

Consequently, the checked-in converter makes future preparation deterministic once the raw edge list, node-community mapping, and two community IDs are supplied, and it reproduces the current prepared graphs semantically from their existing `0/1` mappings. It cannot independently reconstruct the historical community selection from upstream SNAP files until those original IDs or selection artifacts are recovered.
